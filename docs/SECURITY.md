# Security and privacy

- Only public GitHub repositories are supported. Repository identity is parsed and validated; callers cannot supply URLs or hosts for server-side fetches.
- GitHub requests use the fixed API origin, validated owner/repository/branch/blob identifiers, an 8-second timeout, at most one retry for transient transport or 5xx failures, bounded response bodies, concurrency, byte/file/node/evidence budgets, and a bounded analysis response (no retry for rate limits).
- A branch is resolved once. All source reads in one analysis use the resolved commit tree/blob SHA. Source requests verify the path and blob SHA belong to the supplied commit before returning one text file up to 96 KiB.
- Repository source and manifests are untrusted data. The application does not execute repository code, install packages, follow repository URLs, or log source contents/tokens.
- Graph analysis is held only in browser memory. Reloading or using Clear removes it. No database, account or tracking store is configured. Change decisions have a bounded ephemeral server cache described below.
- Without `GITHUB_TOKEN`, all visitors share the deployment's anonymous GitHub REST quota. Rate-limit responses include GitHub's reset delay and a server-side recovery path. For the public deployment, configure a least-privilege read-only token in Vercel; never expose it with a `VITE_*` variable. No process-local limiter is presented as a distributed abuse control.
- The centralized budgets cap analysis at 2,500 eligible tree entries, 180 parsed source files, 80 KiB per file, 1 MiB total source/config text, eight blob requests at once, 500 graph nodes, 1,200 edges, 2,000 evidence items, a 3.6 MB response, and 25 seconds of analysis time.
- Vercel function duration, plan, region, and payload limits can change. This app sets a small internal deadline and a 30-second shared-function cap. Check current account and platform settings before changing the cap; the project needs no paid service or database.

## Jev trust boundaries

- Anonymous users can request deterministic demo decisions. Demo results never invoke TypeSafe or represent measured AI probabilities. Live mode requires a server-only `TYPESAFE_API_KEY`, an operator `CHANGE_IMPACT_ACCESS_TOKEN` of at least 32 characters, and explicit consent. Missing/invalid operator credentials fail before repository collection. Credential comparisons use fixed-length hashes and timing-safe comparison.
- Live requests with a supplied Origin must match the request origin. Bearer authorization does not rely on cookies. No CORS permission is granted to other sites. Keep the operator token private; it grants paid analysis access. Rotate it through environment settings if disclosed.
- Both comparison refs are validated, resolved once and compared by immutable SHA. The public-repository check is performed before fetching commit metadata even when `GITHUB_TOKEN` has private access. There is no client-controlled upstream host, endpoint, model, facts or question definition.
- Only up to 60 public filenames, statuses, numeric line counts and deterministic path signals enter the model state. Credential files, generated output and lockfiles are excluded. Omitted/renamed/truncated or divergent evidence is marked incomplete. Filenames remain untrusted data; question instructions never delegate authority to repository content. Prompt injection cannot alter application authorization or merge policy.
- Source code, patches, commit messages and secrets are excluded from Jev state. The interface explains the data transfer and links the provider privacy terms. Private repository support is deliberately absent.
- Jev requests have an 8-second timeout and **zero retries** to avoid hidden duplicate spend. SDK logging is disabled and its API origin is fixed. Runtime schemas validate answer keys, distributions, rubric, continuous score, Noul probability, confidence and model pin before applying policy. Upstream bodies/headers/messages are never returned or logged.
- Safe diagnostic events contain only an event name, error code and status. Responses use `Cache-Control: no-store`. No browser token persistence or telemetry is introduced. Do not capture the operator token field in screenshots.
- A warm-instance limiter permits at most 10 new live calls per minute; identical in-flight requests coalesce. A 32-entry, five-minute cache includes actor digest, normalized evidence and model/question/policy identity. These optimizations are **not** distributed rate or spending guarantees. Use provider credit limits and protect the operator token. Public GitHub endpoints still consume shared GitHub quota; no new infrastructure is added.
- A review recommendation is advisory. No endpoint approves, merges or blocks a pull request. Security-sensitive paths trigger human review and independent checks; a path heuristic or model answer is not a vulnerability finding.

Verification includes malformed/oversized input, arbitrary-host rejection, private-repository rejection, auth/consent/origin boundaries, filtered source/credential content, cache isolation, invalid upstream schema, provider failures, timeout/no-retry behavior, and browser demo/unavailable states. Passing tests and dependency audits do not establish absence of vulnerabilities.
